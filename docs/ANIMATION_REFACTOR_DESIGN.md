# Animation System Refactor — Architecture Design

> Status: APPROVED (shadcn mode + incremental migration)
> Date: 2025-03-17

## 1. Current Problems

1. **Animations are "docs", not "runnable things"** — `codeSnippets` are template strings, users copy-paste and assemble manually
2. **Preview and Definition are split** — `lib/animations/foo.ts` (data) vs `lib/animations/previews/foo-preview.tsx` (real component), no sync guarantee
3. **Manual preview mapping** — `animation-preview.tsx` has 47 hand-written dynamic imports, every new animation touches 4 files
4. **Identity crisis** — `DesignStyle.styleType: "animation"` in styles vs `Animation` type in animations, blurry boundary

## 2. Design Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Delivery model | shadcn (source code, no npm pkg) | StyleKit is a style reference, not a runtime library. Zero deps for users. |
| Migration pace | Incremental (pilot 1-2, then batch) | De-risk the new structure before committing 47 animations |
| `styles/` animation types | Keep in styles | They have full visual specs (colors, components, philosophy). Animations in `lib/animations/` are pure motion atoms. |

## 3. Target File Structure

```
lib/animations/
  _registry.ts              → Auto-collects all animations (replaces manual index.ts)
  _types.ts                 → Animation, AnimationMeta types (renamed from types.ts)
  scroll-page-turn/
    index.ts                → Re-exports meta + hook + component
    meta.ts                 → AnimationMeta object (lightweight, for listing)
    use-scroll-page-turn.ts → Hook source (real, runnable)
    component.tsx           → <ScrollPageTurn /> wrapper (optional, for complex ones)
    preview.tsx             → Demo component (imports own hook/component)
    README.md               → Usage docs (auto-generated or hand-written)
  flip-card/
    index.ts
    meta.ts
    use-flip-card.ts
    preview.tsx
  fade-in-up/
    index.ts
    meta.ts
    source.css              → Pure CSS version (for simple animations)
    preview.tsx
```

### Key changes:
- Each animation is a **directory**, not a flat file
- Preview imports the **real hook/component**, not a separate implementation
- `_registry.ts` auto-discovers animations via `import.meta.glob` or build-time script
- No more manual `previewMap` — convention-based: `{slug}/preview.tsx`

## 4. Type System Changes

```typescript
// _types.ts
export interface Animation {
  slug: string;
  name: string;
  nameEn: string;
  description: string;
  descriptionEn: string;
  category: AnimationCategory;
  tags: string[];
  trigger: AnimationTrigger;
  difficulty: "beginner" | "intermediate" | "advanced";
  duration: string;
  easing: string;
  cssProperties: string[];
  isGPUAccelerated: boolean;
  previewBg?: "dark" | "light" | "gradient";
  keywords: string[];
  useCases: string[];
  relatedAnimations?: string[];
  recommendedStyles?: string[];

  // NEW: source files for shadcn-style delivery
  sources: {
    css?: string;       // Pure CSS source code
    hook?: string;      // React Hook source code
    component?: string; // React Component source code
    framer?: string;    // Framer Motion variant
  };
}
```

`codeSnippets` array → `sources` object. Typed keys instead of label-based lookup.

## 5. Registry Auto-Discovery

```typescript
// _registry.ts
// Option A: Build-time script generates this file
// Option B: Use dynamic imports with glob pattern

// Build-time approach (recommended for Next.js):
import { scrollPageTurn } from "./scroll-page-turn";
import { flipCard } from "./flip-card";
// ... auto-generated by script

// The script reads lib/animations/*/index.ts and generates imports
```

Build script: `tools/scripts/generate-animation-registry.ts`
- Scans `lib/animations/*/index.ts`
- Generates `_registry.ts` with imports
- Generates `_meta-registry.ts` with lightweight meta
- Runs as part of `prebuild` or on file change

## 6. Preview Auto-Discovery

```typescript
// components/animations/animation-preview.tsx
// Replace manual previewMap with dynamic import by convention

export function AnimationPreview({ slug }: { slug: string }) {
  const Preview = dynamic(
    () => import(`@/lib/animations/${slug}/preview`).then(m => m.default),
    { ssr: false, loading: () => <PreviewLoadingFallback /> }
  );
  return <Preview />;
}
```

One function, zero manual mapping. Adding a new animation = adding a directory.

## 7. Migration Plan

### Phase 1: Pilot (2 animations)
- [ ] Create new directory structure for `scroll-page-turn` and `flip-card`
- [ ] Write real hooks: `use-scroll-page-turn.ts`, `use-flip-card.ts`
- [ ] Preview imports the real hook
- [ ] `_registry.ts` supports both old (flat file) and new (directory) formats
- [ ] Verify: listing page, detail page, code tabs all work
- [ ] Verify: build passes, no regressions

### Phase 2: Tooling
- [ ] Write `tools/scripts/generate-animation-registry.ts`
- [ ] Write migration script: old flat file → new directory structure
- [ ] Update `animation-preview.tsx` to convention-based discovery
- [ ] Add `prebuild` hook to regenerate registry

### Phase 3: Batch Migration
- [ ] Run migration script for remaining 45 animations
- [ ] Delete old `previewMap` manual mapping
- [ ] Delete old flat `lib/animations/*.ts` files
- [ ] Update docs and STYLE_ADDITION_CHECKLIST.md

### Phase 4: CLI Add Command (optional, future)
- [ ] `npx stylekit add animation scroll-page-turn`
- [ ] Copies hook/component source to user's project
- [ ] Respects user's project structure (configurable target dir)

## 8. Backward Compatibility

During migration, both formats coexist:
- `_registry.ts` checks for directory-based animations first, falls back to flat files
- `animation-preview.tsx` tries convention import, falls back to `previewMap`
- No breaking changes to public URLs or API

## 9. What NOT to Change

- `lib/styles/` stays as-is (animation-type styles like card-flip remain there)
- `components/ui/` stays as-is (UI primitives are separate from animations)
- Animation detail page URL structure (`/animations/[slug]`) stays the same
- MCP server and CLI tools — extend later, don't block on this
