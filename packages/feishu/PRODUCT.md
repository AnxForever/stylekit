# 产品介绍

## 一句话

**让 AI 写出来的前端，风格不再随机。**

## 它是什么

一个住在飞书群里的设计规范机器人。你在群里用一句话描述需求，它从 StyleKit 的 146 个设计风格里选出最合适的，把整套可落地的工程包交给你；你用 AI 把代码写出来，贴回群里，它按该风格的规则引擎逐条体检，违规的地方直接告诉你改成什么。

它解决的是设计意图在「人 → AI → 代码」这条链上的三次失真：

1. **说不清** — "想要高级感" 十个 AI 十个理解，每个都不一样
2. **传不准** — 口头对齐的东西，换个工具、换个会话就丢了
3. **写不对** — AI 生成代码时风格漂移，圆角、渐变、阴影处处走样，事后没人查

## 为什么做

StyleKit 收录了 146 个设计风格（每个都有配色 token、组件代码、AI 规则），但此前它的规则引擎只在网站内部生效 —— 真正的用户在 AI 编程助手（Cursor / Claude Code）里写代码时，风格库帮不上忙。

这个机器人把风格库从「网页上参观」变成「工作流里执法」：选型发生在写码之前，验收发生在写码之后，飞书是中间的现场。

## 怎么实现

```
一句话需求 ──▶ AI 语义分析 ──▶ 146 风格全量比对 ──▶ 流式卡片推荐 3 选 1
                                                    │（点按钮选定）
写代码 ──▶ 贴回群里 ──▶ 规则引擎体检 ──▶ 逐条修复建议 ──▶ 再贴 ──▶ 变绿
                                                    │
                      ┌─────────────────────────────┘
                      ▼
         多维表格落库 + 飞书文档《设计规范交付单》
        （23 件产物：AI 提示词 / Cursor·Claude 规则 /
          shadcn 主题 / Tailwind preset / Figma tokens /
          组件代码 / Agent Skill）
```

**飞书在核心链路里的职责**：读取消息、下载参考图、流式展示推理过程、响应卡片按钮、回写多维表格、生成交付文档、接收代码体检 —— 七处，缺一处链路就断。

**AI 在核心链路里的职责**：理解需求、比对风格、生成交付物、解读违规项 —— 同样缺一处不可。

## 带来的价值

- **个人**：从「一句话」到「可开工的工程包」一次对话完成；代码写完不用肉眼查风格
- **团队**：多维表格是项目的风格台账，规范文档是唯一权威，新成员进群即可对齐
- **可复用**：三步装上（`pnpm install` → 扫码 → `dev`），换个 slug 就是你的项目

## 复用性

- 全部代码 MIT 开源，含上手指南（packages/feishu/SETUP.md）
- 机器人依赖的 StyleKit 能力以 npm 包形式发布（stylekit-core）
- 注册走扫码流程，无需手动建应用、勾权限
